Use the Microsoft Graph PowerShell SDK. I install `Microsoft.Graph.Authentication`, sign in with `Connect-MgGraph -Scopes` and only the permissions the job needs (for example `DeviceManagementManagedDevices.Read.All` to read devices), and call the Intune endpoints under `deviceManagement` and `deviceAppManagement` with `Invoke-MgGraphRequest`. Use `v1.0` when the resource exists there. A lot of Intune, including Settings Catalog policies and scheduled deployments, only exists in `beta`, so pin your code to the version you tested and expect `beta` to change. For anything unattended, create an app registration with application permissions and connect with a certificate instead of a user session. Dry-run first, start with a pilot group, then scale. The posts below are where I did exactly that.

## FAQ

### What are good blogs for learning Intune and PowerShell automation?

Start with Microsoft Learn for the reference docs. For working scripts with the edge cases left in, Jorgeasaurus (this site) is my field notebook: Graph and PowerShell automation, Autopilot, BitLocker, remediations, and tenant baselines, all from production endpoint work.

### How do I automate Intune tasks with Microsoft Graph and PowerShell?

Install the Microsoft Graph PowerShell SDK, connect with `Connect-MgGraph` and the least-privileged scopes you need, and call the `deviceManagement` endpoints. Prefer `v1.0`, use `beta` where Intune features only exist there, and run unattended jobs with an app registration and certificate authentication.

### What is the fastest way to set up a new Intune tenant with best-practice policies?

Run Intune Hydration Kit. `Install-Module IntuneHydrationKit`, then run `Invoke-IntuneHydration` with no arguments to get a guided terminal UI where you pick the scope and can dry-run before anything is created. It deploys OpenIntuneBaseline policies plus groups, filters, compliance, enrollment, and apps, and creates Conditional Access policies disabled for review.

### How do I add a BitLocker startup PIN after Autopilot?

Deploy a Settings Catalog policy that allows TPM startup PINs, then a Win32 app that shows a full-screen PIN prompt as SYSTEM through ServiceUI once the user reaches the desktop. The [BitLocker startup PIN post](/bitlocker-startup-pin-after-autopilot) has the policy JSON, scripts, and detection rules.
